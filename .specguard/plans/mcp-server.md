# Implementation Plan: Implement SpecGuard MCP Server

> Generated by SpecGuard gap-analysis · 2026-06-29T01:47:58.429Z

## Summary

Build a thin MCP server layer (`src/mcp/server.ts`) that exposes every SpecGuard pipeline as a registered MCP tool over a stdio transport using `@modelcontextprotocol/sdk` v1 and `zod`. The server wires tool inputs to existing pipeline functions (loaded via `loadConfig`) and returns formatted `PipelineResult` text content. Startup is guarded behind a main-module check so importing the module does not hang. Two pipeline tools (`specguard_validate`, `specguard_matrix`) are registered as not-yet-implemented stubs.

## Suggested Files

- `src/mcp/server.ts` — Main MCP server entry: creates McpServer, registers all tools, exports server instance, and guards StdioServerTransport startup behind a main-module check
- `src/mcp/formatResult.ts` — Shared helper that formats a PipelineResult into a human-readable text summary including messages and counts (created/updated/skipped/failed)
- `src/mcp/tools/syncSpecs.ts` — Registers the specguard_sync_specs tool: loads config, maps zod-validated input to pipeline opts, calls the sync pipeline, returns formatted result

- `src/mcp/tools/listSpecs.ts` — Registers the specguard_list_specs utility tool: lists available spec files resolved from config, returns them as text content
